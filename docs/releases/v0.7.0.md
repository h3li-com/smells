# Smells v0.7.0

## Why this release

Teams adopting a code-smell gate on an existing codebase face two immediate problems:
legacy code already has smells, and CI or coding-agent workflows can accidentally (or
silently) bypass the gate through shallow clones, editable baseline files, growing
`smells: ignore` lists, or noisy size limits on test suites.

Smells 0.7.0 makes incremental adoption and anti-gaming enforcement native to the CLI.
Pull requests and staged commits can now ratchet directly against any Git reference
with `--base <REF>` in memory—with no committed baseline file to tamper with—while
`smells doctor`, fail-closed CI templates, shallow-clone protection, and `test_suite`
source roles keep the whole integration verifiable from day one.

## What was added

- **In-memory Git-reference Debt Envelope ratchet (`--base <REF>`):** Works with both
  `--path` and `--staged` scans, comparing each implementation scope against the base
  commit in memory. Legacy debt stays visible without blocking adoption, new or worse
  blocking smells fail with exit `1`, and paying down debt automatically lowers the
  ceiling (burndown lock). The burndown summary (`base`, `legacy`, `delta`,
  `new_ignores`, and `weakened_rules`) is shown directly on terminal/CI stdout
  (`--format table` and compact `--log` mode), in the Finding Log, and in JSON.
- **Default-on anti-gaming guardrails and run attestation:** Every JSON report now
  includes an `attestation` block (`complete`, `exit_code`, `rules_selected`,
  `rules_measured`, `rules_incomplete`, `history_complete`, `policy_sha256`,
  `suppressions_total`, `ratchet_active`). Under `--base <REF>`, Smells also blocks
  new suppression growth (`blocked_by_suppression_growth`) and weakened required-rule
  policies (`blocked_by_policy_weakening`) by default.
- **`test_suite` support in `source_roles`:** Recognizes declared test suites for
  `pytest`, `unittest`, `vitest`, `jest`, `playwright`, and `cargo_test`. Canonical
  test cases and test blocks exceeding `function_lines` stay scanned, measured, and
  provenance-bound as visible non-blocking `reported_by_role` review signals. Test
  helpers and other rules' findings in test code are non-blocking `indicator`s.
- **`smells doctor` zero-flag health score, diagnostics, and burndown:** New
  `smells doctor [--policy FILE] [--path DIR] [--base REF] [--format table|json]`
  command that works with zero flags—auto-discovering a checked-in policy (or
  falling back with a warning to the built-in Rust, Python, or TypeScript starter
  policy) and `origin/main` / `origin/master` for burndown. Audits policy
  validity and scanner pin, Git history completeness, suppression health,
  `AGENTS.md`/`CLAUDE.md` wiring, and `CODEOWNERS` coverage—prints a colored,
  human-readable terminal report (`NO_COLOR` respected) with a 0–100 Health
  Score, a compact 23-smell diagnostic breakdown (`blocking` vs. `ignored` vs.
  `review`), top 5 hotspot files, and score/blocker/per-smell burndown without
  flooding stdout. Broken prerequisites or scan errors exit `2`; governance gaps
  and diagnostic summaries exit `0`.
- **Measured coverage for CRAP (`--coverage FILE`):** `check` and `doctor` accept
  an LCOV artifact and score each function's CRAP from measured line coverage
  instead of the 0%-coverage upper bound. Functions the artifact does not
  instrument keep the bound. A missing, malformed, unmatched or stale artifact
  exits `2`.
- **CRAP bands:** `function_crap` moves to version `3` with `warning_maximum`
  (5) and `maximum` (10). A score of 5 or less is fine, 6 to 10 is a non-blocking
  warning, and above 10 blocks when the rule is `required` and the score was
  measured from supplied LCOV coverage. Without coverage, scores assume 0%
  coverage and stay warnings, and their explanation says so. The starter policies
  make `function_crap` `required`.
- **Precise `smells doctor` defaults:** The doctor auto-discovers `lcov.info`,
  `coverage/lcov.info` or `target/llvm-cov/lcov.info`. Without coverage it hides
  non-blocking CRAP estimates that assume 0% coverage, says how many it hid in a
  `coverage` check (`estimated_crap_hidden` in JSON), and prints the command that
  produces LCOV for your language. Blocking findings are never hidden. On Smells'
  own source this cut review warnings from 1,352 to 477 without coverage, and to
  562 real ones with coverage.
- **Conventional default policy path:** `--policy` is now optional for `check`,
  `policy show`, and `contracts validate`. When omitted, Smells reads
  `quality-policy.json` from the `--path` directory (the current directory for
  `--staged`, `policy show`, and `contracts validate`). There is no further
  discovery: a missing default exits `2` with
  `no --policy given and <dir>/quality-policy.json not found; pass --policy FILE`.
- **Fail-closed CI gate templates and governance assets:** Copyable templates under
  `examples/ci/` for GitHub Actions (`github-actions-smells.yml`) and Azure Pipelines
  (`azure-pipelines-smells.yml`)—each running as an independent full-history ratchet
  job with always-uploaded artifacts—plus a `CODEOWNERS` snippet and a
  branch-protection checklist in `docs/project-integration.md`.
- **Duplicate Code & Dead Code required by default in starter policies:** Enabled
  `duplicate_functions` and `unused_code` as `required` by default across all three
  starter policies (`examples/quality-policy.json`,
  `examples/python-quality-policy.json`, `examples/typescript-quality-policy.json`),
  backed by deterministic burden contracts documented in `docs/report-interface.md`.

## What was fixed

- **Detector precision from self-scanning:** Running Smells on its own source
  exposed false positives that every user would see. Each changed rule's contract
  moves to version `2`:
  - `data_clumps` reports one closed group per supporting set instead of every
    k-subset.
  - `foreign_accesses` measures individual receiver methods instead of whole
    files.
  - `navigation_chains` counts only consecutive navigation hops, ignoring
    standard adapters and owned-receiver reads.
  - `rust.lazy_class` skips enums.
  - `rust.unused_code` recognizes `main`, test and bench harness entry points,
    and attribute path references.
  - `rust.dependency_contract` counts only accesses from descendant module
    files of the private field's owner. Accesses anywhere else cannot compile,
    so they are name collisions.
  - `function_crap` (all languages) counts cyclomatic complexity on the syntax
    tree. The lexical count read keywords in strings and comments, missed Rust
    `?`, and counted closure `||` and `=>`. Rust now matches cargo-crap on every
    function of Smells' own source (292 of 973 disagreed before). Python follows
    radon and agrees on 99.6% of 4,120 functions; TypeScript follows ESLint's
    `complexity` rule and agrees on 16,741 of 16,744 functions.
- **Calibration against seeded fixture projects:** Scanning small Python,
  TypeScript and Rust projects with one planted instance of each smell exposed
  misses and false positives. These fixes keep each rule's version, so
  existing policies need no edits:
  - `divergent_change` and `shotgun_surgery` take a file's owner from the first
    module below its implementation root, after `src`/`lib` and a top-level
    Python package. Before, every file under `src/` shared one owner, so neither
    rule could match. Both skip the repository's initial commit.
  - `temporary_fields` (Python, TypeScript) no longer counts the constructor as
    a field use.
  - `library_capabilities` (Python, TypeScript) counts assignments only; an
    `a.b.c === v` comparison is no longer a workaround.
  - `rust.port_conformance` no longer requires trait methods with a default
    body.
- **CRAP coverage credit:** Coverage is measured over the function body, not
  its declaration line. Python and JavaScript mark a `def` or `function` line as
  run when the module loads, which gave never-called functions partial credit.
- **Refused Bequest threshold:** `minimum_unused_percent` defaults to 67 instead
  of 80 in the Python and TypeScript registries and starter policies.
- **Duplicate Code threshold:** The starter policies raise `duplicate_functions`
  `minimum_tokens` from 20 to 40. Shorter pairs were mostly visitor and helper
  boilerplate.
- **Shallow Git clones fail closed:** When a shallow clone truncates the 200-commit
  co-change history window, selected history rules now exit `2` with an actionable
  `fetch-depth: 0` error and disclose `history_scope.shallow: true` plus
  `git_history_truncated_by_shallow_clone_fetch_full_history` instead of reporting
  truncated history as clean.
- **Duplicate Code ratchet burden:** A duplicate pair's burden under `--base <REF>`
  now uses its shared token count (`intersection`) instead of `intersection + union`,
  so refactoring one copy to diverge no longer triggers a false regression.
- **Dependency security update:** Bumped `rustix` from `1.1.5` to `1.1.6` to address
  `RUSTSEC-2026-0486`.
- **Mutation-testing harness:** Narrow changed-code PR shards whose diff slice has
  nothing to mutate now pass only when `cargo-mutants` confirms the selection is
  empty; every other missing-results condition continues to fail closed.
- **TypeScript tagged templates with type arguments:** Files using
  ``sql<Row>`SELECT 1` `` no longer exit `2` with a parse error. Tree-sitter-typescript
  0.23.2 recovers them with a zero-width `!`, which Smells now accepts; every other
  parse error still exits `2`.
- **TypeScript import types:** Files using `import("m").T<U>`, `import("m").T[K]`,
  or `vi.fn<typeof import("m").f>()` no longer exit `2` with a parse error. Smells
  reparses a same-length copy with those import types blanked. Dynamic imports are
  unchanged, and any parse error that remains still exits `2`.
- **Raw tagged templates:** Files using ``String.raw`C:\Users\alice\user.ts` `` or
  other tagged templates with `\u` or `\x` escapes that are not valid escapes no
  longer exit `2` with a parse error. ECMAScript allows them in tagged templates.
  In an untagged template or a string they are still a parse error and exit `2`.
  A template that opens on such an escape, as in ``String.raw`\u-1` ``, is covered
  too. Known boundary: a tagged template whose `${}` substitution holds a string,
  comment, regex or nested template is not rewritten and still exits `2`.
- **TypeScript variance annotations:** Files using `class Declaration<out Handler>`
  or `interface Sink<in T>` no longer exit `2` with a parse error. Smells reparses a
  same-length copy with the `in` and `out` modifiers blanked; any parse error that
  remains still exits `2`.
- **Stale cached parse errors:** The portable fact cache key now covers the
  TypeScript compatibility parser. Before this, a scan of unchanged files could keep
  reporting a parse error that the new parser no longer raises.
- **Production calibration:** Smells was scanned against axum, ripgrep, tokio,
  serde, httpx, rich, flask, fastapi, zod, hono, vite and typescript-eslint:
  - Test code never blocks. A finding whose every location is test code (a
    conventional test path, a Cargo `tests`, `examples` or `benches` target root,
    a Rust `#[cfg(test)]` module, or a `#[test]` or `#[rstest]` function) is an
    `indicator` that says it is test code.
  - Duplicate Code reports one finding per family of matching functions instead
    of one per pair. Rust `#[cfg(unix)]` and `#[cfg(windows)]` versions of one
    function are no longer reported as duplicates.
  - Dead Code no longer reports Rust `_` names, items under
    `#[allow(dead_code)]` or `#[expect(unused)]`, exported TypeScript `_`
    declarations, or Python protocol hooks such as `_missing_`.
  - `python.function_arguments` no longer counts keyword-only parameters that
    have a default.
  - Repeated identical signatures no longer exhaust the `data_clumps`
    `maximum_group_combinations` budget.
- **Rust scan errors:** Modules declared from `tests/*.rs`, `examples/*.rs`,
  `benches/*.rs`, `src/bin/*.rs` and `build.rs` resolve next to that file. A trait
  and a derive macro imported under one name, such as axum's `FromRef`, no longer
  stop the scan.
- **Parse errors:** Every parse error names `path:line:column`, and TypeScript
  overloaded call signatures, `export type * from` and members named `abstract`
  now parse.
- **Doctor:** A scan with errors is graded `Incomplete` instead of receiving a score.

## What was removed

- No CLI command, rule, supported language, package channel, or platform target was
  removed.
- No committed baseline file format was added or required; `--base <REF>` computes
  the Debt Envelope directly from Git history in memory.

## Before upgrading

- **Policy pin & starter defaults:** Policy schema remains version `2` and report
  schema remains version `11` (with additive `attestation`, optional `ratchet`,
  `history_scope.shallow`, and `test_suite` `source_roles` fields). Update
  `scanner_version` in your checked-in policy to `"0.7.0"` (or download the matching
  `v0.7.0` starter policy). Note that the `v0.7.0` starter policies now mark
  `duplicate_functions` and `unused_code` as `required`; existing repositories
  adopting them should scan with `--base <REF>` so legacy findings stay within the
  Debt Envelope.
- **Rule version bumps:** Set `version` to `2` for `data_clumps`, `foreign_accesses`,
  and `navigation_chains` in every language, and for `rust.lazy_class`,
  `rust.unused_code` and `rust.dependency_contract`. Set `function_crap` to
  version `3` in every language, with parameters
  `{"warning_maximum": 5, "maximum": 10}`. A policy that still pins an older
  version for these rules fails validation with a rule version mismatch, so
  nothing is silently re-scored.
- **CRAP can now block:** With the `v0.7.0` starter policy and `--coverage`, a
  function whose measured CRAP is above 10 fails the check. Keep
  `function_crap` in `report` mode to see the bands without blocking.
- **Refused Bequest threshold:** To match the starter policies, set
  `refused_bequest.minimum_unused_percent` to `67`. Keeping `80` stays valid.
- **History owners:** `divergent_change` and `shotgun_surgery` now see modules
  below `src/`, so repositories that never saw these review findings may start
  seeing them.
- **Duplicate threshold:** To match the starter policies, set
  `duplicate_functions.minimum_tokens` to `40`. Keeping `20` stays valid and
  reports more short pairs.
- **Coverage:** `--coverage` must point at LCOV generated from the scanned
  checkout. A stale or unmatched file exits `2` rather than being ignored.
- **CI clones:** Ensure GitHub Actions uses `fetch-depth: 0` (Azure Pipelines
  `fetchDepth: 0`). Repositories that previously ran on shallow clones will now
  fail closed with exit `2` when history rules are selected.
- **Known analysis boundaries:** `--base <REF>` cannot be combined with `--evidence`;
  `smells doctor` verifies malformed/unknown suppressions statically, while unused
  suppressions still require a full `smells check`; `duplicate_functions` and
  `unused_code` remain structural indicators that require reviewing `when_to_ignore`
  before suppression; recognized SQL migration bodies continue to be inventoried as
  `migration_body_not_analyzed`. Rust crates that select a module or its path with
  `cfg` (for example `#[cfg(unix)] #[path = "unix/mod.rs"] mod imp;` beside
  `#[cfg(windows)] mod imp;`, as in tokio and serde) exit `2` because active-cfg
  analysis is not implemented. Intentionally broken source such as parser
  fixtures also exits `2`; exclude it with `exclude_directories`.
- **Test code findings:** Findings located only in test code are now `indicator`
  status and no longer block, and Dead Code splits each file's test declarations
  into a separate `<path>::unused-test-declarations` finding.

## How to use it

Install one channel; every channel ships the same native Rust scanner:

```sh
# Python tooling (uv)
uv tool install --force smells==0.7.0

# Node projects
npm install --save-dev --save-exact @mindful-time/smells@0.7.0

# Rust tooling
cargo install --locked --version 0.7.0 smells
```

Download or update the starter policy for your language (for example, Python) and
verify your integration with `smells doctor`:

```sh
curl -fsSLo quality-policy.json \
  https://raw.githubusercontent.com/mindful-time/smells/v0.7.0/examples/python-quality-policy.json
smells doctor
```

Give CRAP measured coverage (the doctor also finds `lcov.info` on its own):

```sh
cargo llvm-cov --lcov --output-path lcov.info
smells check --path . --coverage lcov.info
```

Run a PR ratchet scan against your base branch (or omit `--base` for a full-repo
baseline scan):

```sh
smells check \
  --path . \
  --policy quality-policy.json \
  --base origin/main \
  --format table \
  --log smells-findings.log \
  --report smells-report.json
```
