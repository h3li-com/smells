# Calibration: v0.7.0

This report records how the v0.7.0 detectors were checked against real code before
release. Its purpose is to show whether a finding from `smells check` is worth acting on
in a pre-commit hook.

## Method

We scanned twelve widely used open-source repositories with the starter policies. Rust
used `examples/quality-policy.json`, Python used `examples/python-quality-policy.json`,
and TypeScript used `examples/typescript-quality-policy.json`. Vite and
typescript-eslint need a policy whose `source_roots` name their packages; it has the same
rules and thresholds.

| TypeScript | vite | `86bf3067e` |
| TypeScript | typescript-eslint | `4ba34fd5a` |

We drew a sample stratified by rule and repository: up to five findings per rule in each
language, then a top-up of findings that were new or changed after the first round of
fixes. A reviewer read the code behind every sampled finding, recounted the
measurement, and gave it one of three verdicts:

- **TP**: the rule measured what its contract says, and a competent reviewer would act on
  it.
- **Defensible**: the measurement is correct, but a reviewer could reasonably accept the
  code. Examples are test code, framework-imposed shapes, and deliberate design.
- **FP**: the scanner was wrong. It miscounted, matched the wrong construct, or missed
  code that provides the thing it reported as missing.

For the history rules, the reviewer read each counted commit with `git log`.

We fixed each FP pattern in general form, with a unit test, and rescanned all twelve
repositories after each round. There were three rounds; the third changed no rule
version, threshold or policy mode. Sampled TP and defensible findings that disappeared were
checked by hand to confirm that only false positives went away.

## Release bar

- At least 90% of sampled findings are TP or defensible.
- No rule has two or more FPs in one language.
- No FP root cause repeats three or more times.

## Result

The bar is met. All 316 sampled findings that the final scan still reports (100%) are
TP or defensible. Six of the 322 sampled findings went away in the third round: five
false positives and one defensible finding (`py-036`, a same-class private access in
httpx) that the `dependency_contract` fix now reads as owned.

| Language | Sampled | TP | Defensible | FP |
| --- | ---: | ---: | ---: | ---: |
| Rust | 119 | 24 | 95 | 0 |
| Python | 104 | 33 | 71 | 0 |
| TypeScript | 93 | 20 | 73 | 0 |
| **Total** | **316** | **77** | **239** | **0** |

The sample covers 31 rules. Most verdicts are defensible because mature projects accept
many measured smells on purpose. Long test functions, framework-imposed method sets and
fluent APIs are common examples. Defensible findings are correct, and policies can raise
thresholds or exempt paths where a team accepts them.

### Third-round fixes

After the second round, 7 of 322 sampled findings (2.2%) were false positives. The third
round fixed five root causes in the detectors and reviewed the other two again:

| Rule | Repository | Cause | Result |
| --- | --- | --- | --- |
| `rust.alternative_interfaces` | ripgrep | A method spelling its own type name was compared as a different interface from one spelling `Self`. | Fixed: the owner's own unqualified name reads as `Self`. A path such as `mio::net::TcpStream` still names another type. |
| `python.alternative_interfaces` | flask | Two subclasses of one authored base differed only because one inherits a method the other overrides. | Fixed: method sets include methods inherited from authored bases. |
| `python.library_capabilities` | httpx | `self._response.elapsed = …` sets a property of the project's own class. | Fixed: assignments to an attribute that an authored class declares as a field or `@name.setter` do not count. |
| `typescript.dependency_contract` | hono | An access to a private member of another instance of the same class counted as foreign. | Fixed: members of the enclosing class are owned, and `#private` members never count. Python has the same fix. |
| `typescript.divergent_change`, `typescript.shotgun_surgery` | typescript-eslint | A commit that only adds `eslint-disable` comments counted as a change. | Fixed: file changes whose only edit is a lint, type-checker or coverage suppression do not count. The shotgun finding is gone. The divergent finding drops from 11 to 5 responsibilities over three real changes and is now defensible. |
| `python.divergent_change` | fastapi | The reviewer judged that the file's three changes share one reason. | Reviewed again as defensible: the contract counts co-changed owners, not reasons, and the count is correct. Deciding whether the changes share one reason is up to the agent. |

Every finding the third round removed or added was read by hand. The removals were
suppression-only commits, same-class member accesses, assignments to project-declared
attributes, and constructors that differ only in their own type name. The additions were
sync and async twin classes (including httpx `IteratorByteStream`) whose inherited
methods now enter the comparison, plus findings whose first location moved to the next
counted site.

Every `port_conformance` finding in the first scan was a false positive. The causes were
trait default methods, `cfg`-gated twin declarations, macro-generated methods, ABC
concrete methods and type-parameter constraints read as ports. None of the twelve
repositories has a real omission, so the rule now reports nothing on them.

### Trade-offs

- The `alternative_interfaces` similarity default moved from 8200 to 6200 basis points in
  Python and TypeScript, because the comparison now uses ordered 4-token shingles. A few
  defensible findings fall below the new bar. The httpx true positive
  (`IteratorByteStream`) is reported again now that inherited methods are compared.
- The history rules lose most of their findings. Test, docs, example, script and config
  files no longer count as responsibilities. Mechanical sweeps (formatting, lint, typing,
  whitespace, `doc:` and dependency bumps), reverts and suppression-only file edits no
  longer count as changes. In a blobless partial clone the patches are not read, so
  suppression-only edits still count there.
- `python.library_capabilities` matches declared attributes by name, because Python has
  no types to resolve. A library object attribute that shares a name with an authored
  field or setter is not counted.

## Coverage and boundaries

Each language pack lists 23 smells.

- **Not applicable to Rust.** Refused Bequest and Parallel Inheritance Hierarchies are
  `not_applicable_native_rust`. Rust has no implementation inheritance: traits are
  interfaces, so no type inherits members it can refuse, and there are no parallel
  subclass trees.
- **No findings in this corpus.** These rules ran but found nothing to sample:
  - Python `refused_bequest`, `repeated_dispatch`, `unused_type_parameters` and
    `forwarding_share`.
  - TypeScript `refused_bequest`, `unused_code` and `forwarding_share`.
  - `port_conformance` in every language.

  The calibration says nothing about their precision on other code.
- **Known boundaries.**
  - The history sweep filter recognises reverts only in the `Revert "…"` subject form.
  - A commit that only adds suppression comments still counts as a change.
  - TypeScript `temporary_fields` counts `undefined` in a `Record` value type as an
    optional field.
  - `foreign_accesses` and `library_capabilities` are lexical. They do not resolve types,
    so ownership through a cast such as `(fn as any)._zod` is not seen.
