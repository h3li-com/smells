# Calibration: v0.7.0

This report records how the v0.7.0 detectors were checked against real code before
release. Its purpose is to show whether a finding from `smells check` is worth acting on
in a pre-commit hook.

## Method

We scanned twelve widely used open-source repositories with the starter policies. Rust
used `examples/quality-policy.json`, Python used `examples/python-quality-policy.json`,
and TypeScript used `examples/typescript-quality-policy.json`. Vite and
typescript-eslint need a policy whose `source_roots` name their packages; it has the same
rules and thresholds.

| Language | Repository | Commit |
| --- | --- | --- |
| Rust | axum | `8d8944e` |
| Rust | ripgrep | `3e85c6c` |
| Rust | tokio | `854013a8` |
| Rust | serde | `5be46902` |
| Python | httpx | `7cff5f7` |
| Python | rich | `3a109cc` |

| TypeScript | zod | `d40c3299` |

| TypeScript | vite | `86bf3067e` |
| TypeScript | typescript-eslint | `4ba34fd5a` |

We drew a sample stratified by rule and repository: up to five findings per rule in each
language, then a top-up of findings that were new or changed after the first round of
fixes. A reviewer read the code behind every sampled finding, recounted the
measurement, and gave it one of three verdicts:

- **TP**: the rule measured what its contract says, and a competent reviewer would act on
  it.
- **Defensible**: the measurement is correct, but a reviewer could reasonably accept the
  code. Examples are test code, framework-imposed shapes, and deliberate design.
- **FP**: the scanner was wrong. It miscounted, matched the wrong construct, or missed
  code that provides the thing it reported as missing.

For the history rules, the reviewer read each counted commit with `git log`.

We fixed each FP pattern in general form, with a unit test, and rescanned the
repositories after each round. There were four rounds; the third and fourth changed no
rule version, threshold or policy mode. Sampled TP and defensible findings that
disappeared were checked by hand to confirm that only false positives went away.

The fourth round drew a fresh sample of findings that no earlier round had reviewed. It
covers eleven of the twelve repositories: file reads in the fastapi checkout were blocked
on the review machine, so fastapi has no fourth-round scan. Five checkouts (axum,
ripgrep, httpx, rich and hono) were blobless partial clones. Without blobs the history
rules cannot read patches, so they discount nothing, as designed. To measure those rules
correctly, the final scan of these five repositories read history from full clones at
the same commits.

## Release bar

- At least 90% of sampled findings are TP or defensible.
- No rule has two or more FPs in one language.
- No FP root cause repeats three or more times.

## Result

The bar is met after both the third and fourth rounds.

- **Rounds one to three.** All 316 sampled findings that the third-round scan still
  reports (100%) are TP or defensible. Six of the 322 sampled findings went away in the
  third round: five false positives and one defensible finding (`py-036`, a same-class
  private access in httpx) that the `dependency_contract` fix now reads as owned.
- **Round four.** Of 248 freshly sampled findings, 26 (10.5%) were false positives, which
  missed the bar. All 26 are fixed. All 221 sampled findings that the final scan still
  reports (100%) are TP or defensible. One defensible finding also went away
  (`ty6-001`, see below).

The table covers rounds one to three:

| Language | Sampled | TP | Defensible | FP |
| --- | ---: | ---: | ---: | ---: |
| Rust | 119 | 24 | 95 | 0 |
| Python | 104 | 33 | 71 | 0 |
| TypeScript | 93 | 20 | 73 | 0 |
| **Total** | **316** | **77** | **239** | **0** |

The sample covers 31 rules. Most verdicts are defensible because mature projects accept
many measured smells on purpose. Long test functions, framework-imposed method sets and
fluent APIs are common examples. Defensible findings are correct, and policies can raise
thresholds or exempt paths where a team accepts them.

### Third-round fixes

After the second round, 7 of 322 sampled findings (2.2%) were false positives. The third
round fixed five root causes in the detectors and reviewed the other two again:

| Rule | Repository | Cause | Result |
| --- | --- | --- | --- |
| `rust.alternative_interfaces` | ripgrep | A method spelling its own type name was compared as a different interface from one spelling `Self`. | Fixed: the owner's own unqualified name reads as `Self`. A path such as `mio::net::TcpStream` still names another type. |
| `python.alternative_interfaces` | flask | Two subclasses of one authored base differed only because one inherits a method the other overrides. | Fixed: method sets include methods inherited from authored bases. |
| `python.library_capabilities` | httpx | `self._response.elapsed = …` sets a property of the project's own class. | Fixed: assignments to an attribute that an authored class declares as a field or `@name.setter` do not count. |
| `typescript.dependency_contract` | hono | An access to a private member of another instance of the same class counted as foreign. | Fixed: members of the enclosing class are owned, and `#private` members never count. Python has the same fix. |
| `typescript.divergent_change`, `typescript.shotgun_surgery` | typescript-eslint | A commit that only adds `eslint-disable` comments counted as a change. | Fixed: file changes whose only edit is a lint, type-checker or coverage suppression do not count. The shotgun finding is gone. The divergent finding drops from 11 to 5 responsibilities over three real changes and is now defensible. |
| `python.divergent_change` | fastapi | The reviewer judged that the file's three changes share one reason. | Reviewed again as defensible: the contract counts co-changed owners, not reasons, and the count is correct. Deciding whether the changes share one reason is up to the agent. |

Every finding the third round removed or added was read by hand. The removals were
suppression-only commits, same-class member accesses, assignments to project-declared
attributes, and constructors that differ only in their own type name. The additions were
sync and async twin classes (including httpx `IteratorByteStream`) whose inherited
methods now enter the comparison, plus findings whose first location moved to the next
counted site.

The sample covers 55 rule and language pairs. The 26 false positives had these causes:

| Rule | Repository | Cause | Fix |
| --- | --- | --- | --- |

| `python.shotgun_surgery` | httpx | A commit that only changed the `__version__` string counted `__version__.py` as an owner. | A file whose only edit replaces string literals assigned to `version`, `VERSION` or `__version__` is not changed. | `python.divergent_change`, `python.shotgun_surgery` (2) | flask, httpx | Type-hint and Python-version-drop sweeps counted as changes. | Commit subjects naming type hints, type annotations, Python support or Python versions are sweeps. |

| `typescript.class_methods` (2) | vite | Each overload signature of a vendored `declare class` counted as its own method. | Overload signatures and their implementation count as one method. |
| `typescript.comment_share`, `python.comment_share` | hono, flask | `@ts-expect-error` directives and Sphinx `#:` attribute doc comments counted as comments. | Directive comments (`@ts-expect-error`, `noqa`, `type: ignore` and similar) and `#:` doc comments are excluded. |
| `python.class_fields` | flask | `@name.setter` properties counted as fields beside their backing fields. | Field sets exclude dunder class attributes and setter properties. |
| `python.data_class` | httpx | An `Enum` of constants read as a data class. | `Enum` subclasses are skipped. |
| `python.dependency_contract` | httpx | Enum sunder names such as `_value_` counted as private members. | Sunder names are public. |
| `python.library_capabilities` (4) | httpx, rich, flask | Writes to authored classes or their methods (`setattr(Flask, …)`, `Foo.__rich_repr__.angular = …`) counted as library patches. | Writes to an authored class or its methods do not count. |
| `typescript.library_capabilities` (2) | vite | `process.env` writes counted as library patches. | `process.env` writes are ordinary use. |
| `typescript.foreign_accesses` | vite | Accesses through a local closure's parameter counted as foreign, though every call passes owned state. | Such a parameter is owned. |
| `rust.foreign_accesses` | ripgrep | Bindings from `match *self` arms counted as foreign. | They are owned. |
| `rust.data_clumps` | ripgrep | Constructors of the struct that declares the group counted as supporters. | They do not count. |
| `rust.unused_type_parameters` (2) | axum | A trait's own type parameter, chosen by impl headers and bounds, counted as unused. | A marker trait's type parameters, and trait type parameters an impl header selects with a concrete argument or default, do not count. |
| `rust.unused_code` | axum | Functions nested in an item under `#[allow(dead_code)]` counted as unused. | The allow covers nested items. |

Every fourth-round false positive is gone in the final scan. `py6-081`, the httpx

### Fifth-round check

The fifth round rescanned all twelve repositories, fastapi included, after the code
review fixes. History was read from full clones of axum, ripgrep, httpx, rich and hono.
It reviewed every finding that changed since round four and drew a fresh sample of
fastapi, which round four skipped.

- **Blocking findings did not change** in any of the eleven repositories round four
  scanned. All 66 blocking fastapi findings are true positives or defensible: tutorial
  and test duplicates, `_EffectiveRouteContext` with 45 fields, `APIRouter` with 32
  methods, `analyze_param` at 140 lines and `get_request_handler` with 17 arguments.
- **History counts rose where real edits had been missed.** The stricter
  suppression-only check counts serde `private/mod.rs` changes as 7 (was 6), flask
  `helpers.py` as 8 (was 7), and httpx `_models.py` and `_types.py` as 13 and 8 (were
  12 and 7). Each added commit is a real edit, such as serde `00b1b6b2` removing a
  re-export.
- **One new defensible finding:** flask `sansio/app.py` sets
  `self.jinja_env.auto_reload`, a write onto a jinja `Environment`.

The round found two `library_capabilities` false positives and one false negative:

| Rule | Repository | Cause | Fix |
| --- | --- | --- | --- |
| `python.library_capabilities` | flask | `flask.session.permanent = True` in tests counted as a write through an imported library, though `flask` is the project's own package and declares a `permanent` setter. | An import of the project's own top-level package or module, or a relative import, binds project code, not a library. |
| `typescript.library_capabilities` (3) | zod | Writes to `core.globalConfig` through relative imports of zod's own core counted as library patches. | A relative import binds project code, not a library. |
| `python.library_capabilities` (missed) | fastapi | `monkeypatch.setattr(FormData, "__init__", ...)` on starlette's `FormData` did not count, because a docs tutorial declares an unrelated `FormData` class. | A mutation through an imported name counts even when an authored class shares the name. |

### Trade-offs

- The `alternative_interfaces` similarity default moved from 8200 to 6200 basis points in
  Python and TypeScript, because the comparison now uses ordered 4-token shingles. A few
  defensible findings fall below the new bar. The httpx true positive
  (`IteratorByteStream`) is reported again now that inherited methods are compared.
- The history rules lose most of their findings. Test, docs, example, script and config
  files no longer count as responsibilities. Mechanical sweeps (formatting, lint, typing,
  whitespace, Python-version drops, `doc:` and dependency bumps), reverts, and
  file edits that only change suppressions, only replace a version string or only move
  the file no longer count as changes. In a blobless partial clone the patches are not
  read, so these file edits still count there.
- `python.library_capabilities` matches declared attributes by name, because Python has
  no types to resolve. A library object attribute that shares a name with an authored
  field or setter is not counted.

## Coverage and boundaries

Each language pack lists 23 smells.

- **Not applicable to Rust.** Refused Bequest and Parallel Inheritance Hierarchies are
  `not_applicable_native_rust`. Rust has no implementation inheritance: traits are
  interfaces, so no type inherits members it can refuse, and there are no parallel
  subclass trees.
- **No findings in this corpus.** These rules ran but found nothing to sample:
  - Python `refused_bequest`, `repeated_dispatch`, `unused_type_parameters` and
    `forwarding_share`.
  - TypeScript `refused_bequest`, `unused_code` and `forwarding_share`.
  - `port_conformance` in every language.

  The calibration says nothing about their precision on other code.
- **Known boundaries.**
  - The history sweep filter recognises reverts only in the `Revert "…"` subject form.
  - In a blobless partial clone, the history rules cannot read patches. File edits that
    only change suppressions, only replace a version string or only move the file then
    count as changes. Scan a checkout with full history for exact history findings.
  - TypeScript `temporary_fields` counts `undefined` in a `Record` value type as an
    optional field.
  - `foreign_accesses` and `library_capabilities` are lexical. They do not resolve types,
    so ownership through a cast such as `(fn as any)._zod` is not seen.
